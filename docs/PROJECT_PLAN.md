# 项目计划书 — TARS Assistant

> 计划与进度跟踪。详细技术契约见 `docs/DESIGN.md`，验收记录见 `docs/AVD_TESTING.md`，
> 参数登记见 `docs/RUNTIME_CONFIG.md`，常用意图见 `docs/PRESET_INTENTS.md`。

## 1. 项目目标

在 Android 手机上构建 AI 助手：**原生 App 触发 → Python Agent（安全循环 + 云端模型 API）决策 → 原生 App 执行（无障碍/Shizuku 高权限点击滑动）**。

## 2. 已定决策

| # | 决策点 | 选择 |
|---|--------|------|
| D1 | 主控形态 | 原生 Android App 触发 + Agent 决策 + 原生 App 执行（事件驱动） |
| D2 | 感知方式 | 纯文本 UI 树（无障碍采集 → Python 端摘要），非视觉 |
| D3 | 模型规格 | 云端 OpenAI-compatible 大模型；模型 ID 经私有配置切换 |
| D4 | 目标范围 | 通用对话 + 少量固定技能 |
| D5 | 推理生命周期 | 云端按请求调用；手机不部署模型进程 |
| D6 | 通信主干 | 纯 HTTP loopback（127.0.0.1:8080），不引常驻通道 |
| D7 | Termux:API 定位 | 感知插件（剪贴板等），不作通信主干；语音用 SpeechRecognizer |
| D8 | Agent 环境 | 裸 Termux + venv（非 proot 常驻容器） |
| D9 | 测试环境 | AVD 优先（Google APIs 镜像） |
| D10 | 执行侧路线 | 原生 Android（Kotlin），无障碍 + Shizuku，替换 Tasker |
| D11 | 触发分期 | 一期=定时+通知+悬浮语音；常驻唤醒词二期 |
| D12 | 决策层归属 | 决策层恒用 Python；云端只提供模型 API；执行侧仅 HTTP client + 动作执行 |

### 已完成阶段摘要

- **阶段 0-1**：文档体系、git、四 JSON Schema（task_request/agent_response/action/ui_tree）、`bridge/validate.py`。
- **阶段 2**：`server.py`（/agent/run、/health）、`ui_summarizer.py`、`agent_loop.py` 自研安全循环 + schema 校验兜底；单测全绿。
- **阶段 3**：云端接入（`config/cloud.yaml` 私有配置）、可 mock LLM 客户端、可靠性重试策略；设备内验证。
- **阶段 4**：无障碍 UI 采集 + 动作执行、Shizuku swipe/type 回退、HTTP client、安全层（白名单/确认/失败收敛/观察新鲜度/历史与动作边界）、AVD 验收。

## 4. 风险清单

| 风险 | 缓解 |
|------|------|
| 3B 模型 agent 能力弱 | 结构化 JSON + schema 校验兜底 + 失败重试；复杂任务可换更大模型 |
| UI 树超长撑爆上下文 | ui_summarizer 压缩为可交互节点，单屏 ≤500 token |
| 高权限自动操作误伤 | 动作白名单 + 敏感操作确认（三层兜底） |
| Kotlin 原生工程量大 | 执行侧仅采集/执行/HTTP，决策复用 Python |
| 原生触发入口后台限制 | AlarmManager 精确闹钟 + 前台服务保活 |
| 裸 Termux 编译依赖难装 | 优先纯 Python/预编译 wheel |
| 云端不可用/超时 | 连接/超时、429、5xx 有界重试；认证/其他 4xx 立即失败；不降级为自动执行 |
| Gmail 建议组件图层采集缺口 | 见下方「关键判断」：采集需覆盖多窗口图层（方案 A） |

## 5. 关键判断（按时间记录）

| 日期 | 判断 |
|------|------|
| 2026-08-23 | **Gmail 建议组件 = 第二图层，采集只采了第一层**：写邮件界面为第一图层，录入收件人后弹出的建议卡（peoplekit）为第二图层（独立浮层窗口）。执行侧 `rootInActiveWindow` 只采第一图层，建议卡未进采集树 → 大模型从未收到"建议卡"这一决策项，只能点第一层节点（落到被覆盖的无效位置）。`adb uiautomator dump` 能见建议卡（完整窗口树），而 UI 采集树始终没有（单窗口）——印证了这一点。**修复方向**：采集方式改为覆盖多窗口图层（无障碍 `getWindows()` 遍历所有可见窗口，按 z-order 合并、过滤无关浮层、控制 token），使模型看到视觉所及的完整界面。 |
| 2026-08-22 | Gmail 输入执行层修复：`findNode` 命中容器 ViewGroup 导致 ACTION_FOCUS/SET_TEXT 失效；`ActionExecutor.findEditableNode` 向下解析实际输入节点 + 两端谓词统一 contains 语义。 |
| 2026-08-22 | 观察新鲜度升级：`awaitFreshUiAfter` 以**前台包名变化为主信号 + XML 差异为辅 + 无障碍事件序号为刷新信号**，修复跨应用切换误判"无更新"。 |
| 2026-08-22 | 决策轮数上限 8→12（应对突发组件耗尽观察预算）；history 上限 7、单轮动作上限 8 不变。 |
| 2026-08-21 | 架构迁移：手机保留 Termux Python Agent + 原生执行侧，云端仅提供模型 API；清理本地 llama.cpp/GGUF。 |

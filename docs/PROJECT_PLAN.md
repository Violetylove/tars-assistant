# TARS Assistant 项目计划与进度

> 当前有效契约见 `docs/DESIGN.md`。本文件保留项目阶段、未完成边界和关键变化，避免与部署、
> 配置和验收文档重复。

## 目标

构建 Android AI 助手：原生 App 负责触发、UI 感知与受限执行；Termux Python Agent 负责安全决策；
云端仅提供 OpenAI-compatible 模型推理。

## 已交付能力

- Android 对话式任务界面、运行状态、复制/重发、清除记录和任务终止。
- 无障碍、通知、定时、悬浮语音等一期入口；所有自动触发均先形成待处理任务，用户显式发送。
- 多窗口层 UI 采集、稳定 UI 新鲜度门控、有限 history 与 UI diff 上下文。
- 用户可配置 Agent 地址、超时和轮数；独立应用列表实时刷新并限制 `launch` 目录。
- Android 前台敏感确认浮层、双端动作白名单和失败收敛。
- Android/Agent 可按同一短 session ID 联合诊断；Android 日志仅由用户主动上传。
- Git tag 驱动 APK 构建和 GitHub Release 发布。

## 当前待验证与后续候选

| 项目 | 状态 | 说明 |
|---|---|---|
| 多应用真机回归 | 持续 | 复杂应用需要以真实无障碍树验证，不能用单一 Gmail 场景代表通用能力 |
| 常驻唤醒词 | 暂缓 | 受 Android 权限与后台限制影响 |
| 精确业务启动策略 | 评估中 | 维持“用户授权包名 + launcher Intent”安全边界，不能开放任意组件/URI |

## 风险与控制

| 风险 | 控制 |
|---|---|
| 模型输出不可靠 | JSON schema、Android 二次校验、动作/轮数边界与失败收敛 |
| UI 过长或场景变化 | 最多 60 节点、有限 history、差分上下文、稳定树门控 |
| 高权限误操作 | 动作目录、敏感确认、Shizuku 参数限制、用户授权应用列表 |
| 云端失败 | 有界重试；认证和其他 4xx 直接失败，不自动降级执行 |
| Android 时序差异 | 多窗口根回退、空骨架过滤、前台包名匹配和双采样稳定判定 |
